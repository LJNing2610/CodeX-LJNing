# 全局标准操作流程

> 只保存可复用的通用流程。  
> 公开镜像不写入个人设备、账户、会话或项目私有信息。

## SOP-001: 新项目初始化

1. 使用小写中划线英文名创建项目目录。
2. 从 `_template/` 复制标准文档。
3. 填写需求、技术栈和验收标准。
4. 确认项目中没有密钥、隐私数据和大型二进制后再决定是否纳入 Git。

## SOP-002: 日常任务流程

1. 阅读根目录 `README.md`、本目录三份全局文档和相关项目文档。
2. 先检索现有实现和调用链，再确定最小方案。
3. 实施并运行与风险相称的验证。
4. 只沉淀去隐私、可复用的技术结论。
5. 检查变更范围，提交并同步到 `origin/main`。

## SOP-003: 仓库同步与隐私边界

1. 运行 `git status`，只加入本次任务相关文件。
2. 检查密钥、个人路径、账户标识、聊天记录、会话、日志、转储和安装包。
3. 运行 `git diff --cached --stat` 检查变更范围。
4. 使用能说明任务范围的提交信息。
5. 推送到公开镜像仓库，并确认没有敏感内容。

以下内容不得进入仓库：

- 姓名、学号、联系方式、账户标识和个人画像
- 本机用户名、网络地址、设备序列号或远程访问地址
- API Key、OAuth Token、Cookie、登录状态和配对数据
- 聊天、记忆、会话、数据库、崩溃转储和运行日志

## SOP-004: AI 风格与配置恢复

1. 在新设备安装 Codex 并至少启动一次。
2. 安装 PowerShell 7 和 Git；按需安装 Headroom、Codex++。
3. 克隆公开仓库并关闭正在运行的 Codex/Codex++。
4. 运行 `ai-config/restore.ps1`。
5. 需要应用配置骨架时运行 `ai-config/restore.ps1 -ApplyConfig`。
6. 在本机重新登录、填写模型 API Key，并完成 MCP 授权。
7. 验证全局规则、自定义 Skill、Ponytail 和增强脚本是否加载。

## SOP-005: 刷新 AI 配置快照

1. 运行 `ai-config/export.ps1`。
2. 确认脚本的密钥扫描通过。
3. 检查快照中没有个人资料、记忆、会话、主题或完整设置。
4. 提交 `ai-config/` 变更并推送。

## SOP-006: 破坏性操作

1. 明确目标绝对路径和影响范围。
2. 确认操作在用户授权范围内。
3. 优先使用可恢复操作，并保存必要备份或回滚脚本。
4. 操作后验证目标状态，而不是只检查命令是否返回成功。
