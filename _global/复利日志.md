# AI 工作规则与复利记录

> 记录可跨项目复用的 AI 工作方式、工程规范和验证方法。  
> 不记录个人画像、设备信息、账户信息、聊天记录或会话历史。

## 当前规则

### 2026-10-27: [规范] 语言与输出

- **场景/任务**: 日常协作与代码任务。
- **内容**: 默认使用中文；先给结论或结果，再补充必要证据；保持简洁、直接、可验证。
- **原因/背景**: 降低理解成本，避免重复解释已经确认的事实。

### 2026-10-27: [规范] 省 Token

- **场景/任务**: 文件检索、诊断和长任务。
- **内容**:
  - 文件尽量一次读取，过长时按段读取。
  - 独立检查优先并行。
  - 使用 `rg`、结构化命令和精确过滤。
  - 已验证的结果不重复验证。
  - 少截图、少贴长日志，只保留影响决策的证据。
- **原因/背景**: 把上下文留给实现和验证，而不是重复读取无关内容。

### 2026-10-27: [规范] 写代码前先思考

- **场景/任务**: 编写、修复、重构和评审代码。
- **内容**:
  - 先理解目标、调用链、输入输出和边界条件。
  - 修改共享逻辑前搜索调用方，优先修复根因。
  - 明确输入验证、错误处理、安全和可访问性要求。
  - 需求含糊时采用最小可解释假设；会显著改变结果时再询问。
- **原因/背景**: 最短的 diff 只有在位置正确时才有价值。

### 2026-10-27: [规范] Ponytail 最小实现

- **场景/任务**: 选择实现方案和依赖。
- **内容**: 依次检查是否真的需要、是否已有实现、标准库、平台原生能力、现有依赖、单行方案，最后才写最少可运行代码。
- **禁止**: 单一实现的接口、投机性工厂、无用配置层和“以后可能会用”的脚手架。
- **原因/背景**: 删除优先于新增，简单优先于聪明，最小有效变更优先。

### 2026-10-27: [规范] 验证与安全

- **场景/任务**: 修复、配置、部署和迁移。
- **内容**:
  - 诊断先取证，再下结论。
  - 验证真实结果，不只验证命令退出码。
  - 破坏性操作先确认绝对路径并提供备份或回滚入口。
  - 非平凡逻辑保留一个最小可运行检查。
  - 密钥、凭据、账户标识、会话和日志不得进入仓库。
- **原因/背景**: 可回滚和可复现比“看起来成功”更重要。

### 2026-10-27: [规范] 知识沉淀

- **场景/任务**: 完成任务并发现可复用经验。
- **内容**:
  - 通用规范写入本文件。
  - 通用问题写入 `踩坑日志.md`。
  - 可复用步骤写入 `SOP.md`。
  - 项目决策和项目专属问题写入项目文档。
  - 只沉淀去隐私、可复用的技术结论。
- **原因/背景**: 让后续任务复用方法，而不是复述个人经历。
